# Исправление запуска эмулятора 0.6.1

Пользователь сообщил о пустых экранах и «Ошибка DSP: undefined» при открытии скачанного HTML двойным щелчком в Chrome. Предыдущие проверки запускали автономный HTML через HTTP и не покрывали отказ фонового Worker. При блокировке Worker политикой `worker-src 'none'` удалось воспроизвести точно такое же сообщение и отсутствие кадров.

Причина `undefined`: обработчик без проверки использовал `event.message`, хотя при отказе запуска браузер может прислать обычный `Event` без этого поля. Резервного способа вычисления не было, поэтому интерфейс работал, но изображение не появлялось.

Исправлено:

- Модульный Worker с top-level await заменён обычным Worker с асинхронной инициализацией внутри общего runtime.
- При отказе создания, ошибке загрузки, отсутствии Worker API или отсутствии ответа за 5 секунд автоматически запускается тот же WASM в основном потоке. Браузерные ограничения не отключаются. Внизу появляется «совместимый режим»; интерфейс может реагировать медленнее из-за вычислений в основном потоке.
- Настройки, изменённые во время загрузки, и состояние паузы сохраняются при восстановлении. Сообщения от остановленного Worker игнорируются.
- Ошибки HTTP, компиляции WASM и отсутствие WebAssembly показывают причину; приложение не остаётся бесконечно в «DSP запускается».
- В автономный HTML включены оба способа запуска. Для его работы не нужны сервер, npm или внешние ресурсы.

Добавлено 6 тестов runtime/client и 7 браузерных сценариев. Проверены основной canvas и LCD-preview, совпадение пикселей Worker/совместимого режима, изменение ручек на паузе, чёрный микс, возобновление, автономность и работа при запрете Worker. [Отчёт браузерных регрессий](../../hardware/verification/browser-compatibility-summary.json).

Прямой запуск `file://` в облачном Chromium по-прежнему запрещён политикой тестового хоста. Его не выдаём за выполненный тест. Вместо него проверены автономный документ с opaque origin, запрет всех последующих сетевых запросов и реальный отказ Worker через CSP. Эти тесты закрывают ранее пропущенные пути запуска и восстановления, но не подменяют проверку конкретной установки Chrome пользователя.

Скачайте новый `dist/VideoSynth-R1.html`, замените старую копию и откройте её в Chrome. Внизу страницы должна быть версия **0.6.1**. Аппаратные файлы, DSP-алгоритм на C и выводы о производительности ESP32-P4 этим исправлением не изменены.
